비슷한 점
Java interface처럼 "무엇을 할 수 있는지(함수 시그니처)"만 미리 선언하고, 실제 구현은 다른 곳(.cpp)에 있다는 점은 유사합니다.

다른 점 (더 중요함)
Java interface는 필드(멤버 변수)를 가질 수 없고 함수 몸체도 없는 순수 선언인데, Account.h는 private 섹션에 실제 데이터 멤버(owner, balance)까지 갖고 있습니다 (Account.h:50-51).
Java interface는 인스턴스화할 수 없지만, 이 헤더는 Account acc("홍길동", 10000);처럼 직접 객체를 만들 수 있는 완전한 클래스 선언입니다.
Java interface는 다른 클래스가 implements해서 각자 다르게 구현하는 "계약(contract)" 역할인데, Account.h는 그런 다형성 목적이 아니라 그냥 "클래스 전체 설계도를 선언부/구현부로 나눈 것"입니다 (컴파일 단위 분리가 목적).

더 정확한 비유
굳이 Java에 빗대자면 Java interface보다는 "클래스의 시그니처만 뽑아놓은 것" 혹은 컴파일된 .class 파일의 public 메서드 목록에 가깝습니다. 즉 Java에는 이렇게 선언/구현을 파일로 분리하는 개념 자체가 없어서(보통 한 .java 파일에 다 있음), 정확히 대응되는 개념은 없다고 보는 게 맞아요.
참고로 선택하신 33번 줄의 &는 인터페이스 개념과는 무관하고, getOwner()가 문자열을 복사하지 않고 참조(reference)로 반환해서 불필요한 복사를 피하는 최적화 문법입니다.
